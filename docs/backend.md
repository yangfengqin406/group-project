# 真实后端接入

校园业务现有可运行的本机真实后端 `backend/campus/`：独立密码账号、文件存储、SQLite 与 A/B/C 统一 RPC，执行 `npm run campus:local` 启动，详见[接入契约](local-campus-backend.md)。未创建云环境或部署公网。`server/landlord/` 仍是独立访客牌桌，不替代校园账号。以下步骤用于继续接入公网/微信环境，不能据本机服务宣称生产部署完成。

1. B 与团队确定真实登录方式、开发云环境、数据集合和权限，A/C 实现各自模块。多人使用成员授权，不共享管理员密码。
2. 先做 auth.login 和 user.getProfile。微信可提交真实登录 code；H5 需要单独可用的认证路线，不能把微信授权静默搬到浏览器。不要写“输入任意昵称即真实登录”。
3. 接入所选 SDK 或实现 `POST /rpc`。src/services/transport.js 是唯一接入点，按 docs/interfaces.md 返回 envelope。SDK 凭证/服务端密钥不要进入前端。
4. 配置 `.env`：VITE_API_MODE=http 和真实 HTTPS VITE_API_BASE_URL；重启开发或重新构建。HTTP 失败应报错，不可返回 mock 成功。
5. 接入真实上传，替换 publish.vue 中 mock 图片分支。upload.create 给出受控上传地址/存储信息，上传完成后 upload.confirm 返回 imageId 和可展示图片地址；不允许无限制公开桶写入。
6. 搭子邀请使用数据库事务处理容量和状态，防止两人同时接受超员。幂等键应和用户、操作、参数一起校验；通知按事件去重。
7. C 接入真实留言、会话与站内通知；订阅授权和服务端发送后续接入。H5 即使没有微信订阅仍能在消息中心读取结果。
8. 在两个账号、两台设备上验收。清空本机存储后内容仍存在才算真实持久化，两个设备能看到对方操作才算真实通信。

这个骨架没有提供一键可用的生产后端；后续后端代码请放 backend/ 并按模块拆分，不要把真实业务继续堆在 src/mock/engine.js。

## 独立局域网牌桌服务

`npm run game:local` 先构建校园业务为 mock、牌桌地址为 `/game` 的 H5，再运行 `server/landlord/index.mjs`，默认监听 `0.0.0.0:8787`。同一服务同时托管 `dist/build/h5` 和 `/game/rpc`；`npm run game:serve` 只启动服务，不构建或修改已有 H5 配置。三设备操作与连接排查见[部署说明](deployment.md#局域网三人斗地主本轮本地实现)。公网托管、三台物理设备与微信联网尚未验收。

牌局通过 `src/services/landlord.js` 和独立 `game-transport.js` 调用，不经过校园业务的 mock/http 切换。`VITE_GAME_BASE_URL` 是公开服务地址，不能放密钥；为空时显示未配置。访客令牌由服务签发，客户端按服务地址保存，只用于本人牌桌；不发送校园账号令牌，不把昵称入座计为真实校园认证。

服务负责洗牌、三人匹配、叫分、合法出牌、轮次、胜负和托管；每位访客只读取本人手牌，对手仅公开张数及已出的牌。在线人数按45秒内有请求的独立访客计算，前台约1秒轮询；正常回合20秒，超时或离线明确切为托管，用户返回后可接手。写操作按访客、操作编号及参数指纹去重，保留最近256个成功操作回执；同编号换参数拒绝，旧牌桌版本冲突后重新读取，不能把无期限重放保证写成已实现。

访客、匹配队列、牌桌和操作回执均在进程内存，重启即清空。结束牌桌10分钟后收起，活动旧局最长30分钟后收起且不编造胜负；无牌桌的闲置访客6小时后清理。上述清理由服务时钟执行，不由页面直接修改。当前服务不含持久化、多实例协调、生产部署或货币结算，也不与衣柜珍珠互通；后续校园后端仍按上方分工接入。
