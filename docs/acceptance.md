# 骨架检查与真实版本验收

## 本机演示走查

1. npm ci、npm run dev:h5；首页为整屏四栋房子的广场，场景内有“私信”和“我的”入口；进入普通底栏页面后，广场/消息/我的栏目正常恢复。
2. 点找搭子建筑，等宠物走到门口进入列表；找到小林的电影计划，进详情→“查看相近计划”。只推荐小桃的电影计划，不推荐小禾散步。
3. 邀请小桃后返回自己的家，切换小桃→消息→接受。再切小林确认目标满员；小桃原计划已关闭。不会自动确认。
4. 切小林→二手台灯详情→联系→留言；消息入口找到会话，原商品链接能返回详情。切小桃可查看并手动回复；不存在自动假回复。
5. 失物列表可分别按丢失/拾获和卡片/钥匙/杂物筛选；发布必须选择两级分类并添加 1～3 张图片。失物详情可公开评论或私信，私信进入共用消息并保留原失物链接；作者可标记“已完成”。点任意作者名称进入其公开主页，看各模块发布，不会进入“自己的家”。
6. 发布二手/失物/搭子/技能互助，返回列表并搜索；收藏与举报有明确结果。消息中心能汇总并筛选二手、失物、搭子会话，每条会话可返回原内容。重启后文本演示数据保留；临时图片不承诺永久。
7. 切换身份后不能修改别人的发布、看不属于自己的会话或通知。生产权限仍需后端实现。
8. H5 点击接收匹配通知显示站内消息替代说明；微信模板未配置时显示待配置，不伪造发送成功。
9. npm run check、npm test 和两个 build 均通过。

PR #6整合补充（2026-10-21）：在独立本机演示身份分别发布二手与失物，选择真实本地PNG，二手以imageIds解析详情图片，失物以images预览/删除/重选并保存；依次切换二手闲置/求购和失物分类/丢失拾获，确认不互相过滤。编辑另一演示身份的资料头像，评论失物并联系二手/失物，在同一消息中心查看原内容链接。合并后重新运行check、全量test及两端build；模拟登录/临时图片不计为真实认证或公共云上传验收。

1. 用 320px、390px 手机宽度、手机横屏和桌面打开广场：场景铺满可用窗口，无日期、大标题、计划长列表及下方暂停/重置工具栏。宠物、门牌与场景导航大小适中，没有横向页面溢出；旋转设备或调整窗口后布局更新，不要求强制锁定横屏。

3. 四栋楼的悬挂小木牌与屋顶配色协调，搭子/失物/二手/自己的家分别能辨认双叶、放大镜、提袋、家图形；缩放后文字和热区仍可用。分别点建筑本体及门牌，先看到宠物沿步道和对应支路走向门口，抵达后才跳转对应模块，不点击即跳、不穿中心树岛、不重复跳转。途中点另一个建筑或步道应替换目标；途中通过“私信”“我的”或“我的宠物”离开后，旧目标不能在后台继续触发跳转。离开广场停止场景计时；回到普通底栏页面时原生栏目恢复。开启减少动态效果设置，检查装饰动画减少且明确点按的移动仍可用。

## 宠物搭配专项

1. 自己的家点“去搭配”，或广场点“我的宠物”，打开同一搭配页；“选伙伴”中蘑菇、水豚、兔子、松鼠使用透明精绘像素插画，轮廓不同，切换物种不会留下上一种无效耳朵/帽型。名字和说明位于预览场景下方，不叠住角色；手机 320/390px、横屏和桌面均无横向溢出。
2. 逐一更换原色、苔绿、杏桃、淡紫、耳朵或帽型、配饰，预览即时变化。“看背面/看正面”显示真正的后脑、帽檐、尾巴或配饰背部，背面不保留脸部五官，也不以左右翻转代替；每种耳朵/帽型均检查正背面对应资源。“试试走路/停一停”可操作，四种形象完整显示，精绘边缘和透明区域无白底或裁切。
3. 点“我的原创”，在“画正面”的 32×32 画布选择 16 色之一，用“画笔”和 1/2/3 格笔刷点画、拖画；“橡皮”可擦除，“撤销”撤回一笔，“清空画布”需确认。点“画背面”编辑另一张画，来回切换正背面应保留各自草稿；在“选伙伴/我的原创”间切换也保留各自未保存搭配。
4. 在当前“画正面”或“画背面”点“导入 PNG”，选择本地 PNG 后对应预览更新，另一面不被覆盖；取消选图保留原稿。导入图若要手绘，按页面提示先“清空画布”。只导入背面、正面留空时不能保存；有非空正面、背面留空时可以保存，预览背面明确提示“还没有背面”，不自动生成或镜像冒充。原创的“试试走路”使用整体轻摆，不伪造逐肢体动画帧。
5. 分别导入非 PNG、损坏 PNG、超过 256 KiB、任一边超过 512 像素或无法解码的文件，应明确报错并保留已有画稿；合规 PNG 可导入。导入只读取用户选择的本地文件，不请求外部图片链接或宣称已云上传。
6. 为预设或原创起名（例如“青团”），点击“保存并去广场”，自己的角色外观和名字同步；刷新后仍保留。分别切换演示身份编辑并保存，再切回原身份，名字和正背面数据各自独立；编辑新草稿不能改写另一个身份或上次保存的数据。
7. 空白或超过 12 个 Unicode 字符的名字不能保存；错误时草稿保留，名字暂时清空仍可切换预设物种。“还原搭配”恢复已保存版本。页面内“回到广场”先确认放弃修改，系统返回不保存草稿。
8. 真实模式读取/保存接口失败时明确显示错误，不能转为演示成功；原创保存明确提示暂不支持云端保存，返回 NOT_IMPLEMENTED，保留画稿且不跳到广场。预设继续使用原有 RPC；微信开发者工具、真机和真实账号同步需另验。

## 池边钓鱼与休息亭专项

1. 在全景与探索视图检查西南小路、池边栈台、北侧小路与开放亭，横竖窗口下连接自然、热点可达，四栋业务房子保持不变。点场景池边或顶部“池边”，宠物先走到栈台才打开“池边垂钓”；途中改点其他目标或离开页面，不应继续打开旧弹层。
2. “钓一会儿”中点“抛一竿”，等待“咬钩啦！”再点“收竿！”，看到往返标尺后，在绿色区域点“稳稳收线”。成功显示鱼名，累计次数与“我的小鱼册”相应增加；首次成功获得小荷叶，可以点“戴上小荷叶”，再次操作不得重复增加本次奖励。
3. 错过咬钩、让收线落在绿区外或等待超时，应显示鱼儿游回池塘的结果，不增加钓获或装饰；可点“再来一竿”重试。新抛竿后旧编号不得成功收线，重复或他人编号不得重复发奖；服务边界还需拒绝客户端伪造时间、成功、鱼种、奖励和身份参数。
4. 进入“衣柜与鱼册”中的“我的衣柜”并查看“我的小鱼册”：首次成功必有小荷叶，后续成功允许无装饰，按 35% 概率获得小荷叶、芦苇结、水泡星三种之一，重复获得数量累加到同一衣柜；衣柜不应只展示这三件。已拥有装扮可“穿戴/脱下”，不消耗数量。关闭“收起”回到广场，预设和原创伙伴均显示独立装扮；刷新后仍保留。
5. 宠物页点“打开衣柜”直接打开同一“我的衣柜”。原创模式打开收纳袋时先移除原生画布，关闭后画稿完整恢复，微信需确认画布不会浮到弹层上。穿戴或脱下后，关闭面板继续编辑外观；“还原搭配”或放弃外观草稿不应撤销已经保存的穿戴状态。预设外观仍是五字段，原创仍是既有六字段，不能将 ornament 或 wardrobe 写入 pet.save。
6. 在同一设备切换演示身份，鱼册、次数、装扮数量与当前穿戴分别保存，切回原身份仍保留；修改返回状态不能污染保存数据。关闭、切页或后台隐藏后停止弹层计时，重开读取服务当前状态，过期抛竿不能继续获奖。真实接口不可用时显示错误，可“重新读取”，不能回退演示钓获或奖励。
7. 点亭子或顶部“亭子”，宠物沿北侧小路抵达后打开“四人休息亭”，四座均显示空位，明确真人匹配与麻将未开放。“先去找牌友”打开既有搭子页，不显示虚构用户进队，也不启动牌局。

## 分类衣柜与潜水专项（2026-10-20 本地验收清单）

1. 使用没有衣柜、钓鱼或潜水记录的新演示身份首次打开“我的衣柜”：七类标签为发型、头饰、衣服、鞋袜、背包、手持、挂饰，目录合计 23 件；拥有物为空、各槽未穿戴、珍珠为 0、通关记录为空，不赠七件入门物。重复打开和刷新仍为空，不出现“入门赠送”或“礼物已收好”。切类可查看名称、来源、待收集状态及目录标价。升级前已经拥有的物品、数量、珍珠和穿戴应原样保留，不能因新门槛清空或要求重新通关后才准穿。

3. 使用带旧钓鱼数量与单件佩戴的演示存档：三种旧装饰数量不丢失，原佩戴迁入对应槽；重复读取不增长数量。在衣柜更换同槽装扮后，再读旧钓鱼状态不得抢回原佩戴；钓鱼新掉落和兑换旧三种装饰也不重复迁移。此项可结合服务测试验证，不通过页面伪造存储成功。

### 穿戴视觉走查（2026-10-20 更新）
