# H5备用交付方案与上线条件

2026-10-26 · A（杨凤琴）汇总。沿用现有uni-app，同一套源码交付H5和微信，不重写原生小程序。

## 方案一：老师远程访问的固定备用入口

直接提供[校园生活广场H5](https://yangfengqin406.github.io/group-project/#/)。本次首页HTTP200，[Pages部署](https://github.com/yangfengqin406/group-project/actions/runs/40334772937)成功且对应main的`0f42152`；后续版本以最新成功部署为准。

交付说明可直接使用：**“微信审核完成前，请通过H5浏览课程演示。当前为虚构的浏览器本机数据，不是已开放运营的校园服务。”**

老师可浏览四屋、二手/搭子/失物、消息与宠物玩法。每个浏览器独立保存演示记录，不承诺不同设备共用发布或消息；切换演示身份不代表真实登录。演示前用将要展示的电脑和手机实际打开链接，不只检查首页200。

本次独立浏览器单页走查最终可见地图、角色、四屋热点与底栏，30个资源响应均2xx且无运行异常。不过首次图像明显晚于DOM出现：4.7秒截图仍不完整，继续等待后才完整；未测图像全部就绪的精确时点。因此展示前应预先打开并确认画面，同时保留下述现场方案，不能承诺所有校园网络下冷启动都快。

## 方案二：现场展示真实账号和持久化业务

使用Node22.22.0，项目根目录执行`npm run campus:local`，保持服务终端运行；当前8788已运行时复用，不要重复占用端口。主机从`http://127.0.0.1:8788/#/`进入，地址以服务当次输出为准。

准备两个测试账号，分别用普通窗口和无痕窗口展示实际上传、发布、联系、留言和重启保留。记录已实现的独立账号、SQLite和文件存储；不将其称为微信登录或学籍认证。两台手机/校园网互访需现场实测，不能用两个浏览器冒充物理设备验收；10.x私网地址不能作为老师远程交付链接。

## 方案三：现场网络不通时的本机演示

提前完成`npm ci`，在线时执行`npm run game:local`生成根路径H5并试跑。后续可在已有构建上执行`npm run game:serve`，从终端显示的8787地址进入，无需现场下载依赖或重新构建。

该入口的校园内容仍是演示数据，牌桌是独立访客内存服务。依赖外网的示例照片可能不可用，现场演示以本地广场、文本业务和宠物为主。不要双击index.html使用file://运行，也不要把Pages的/group-project/产物直接当根路径版本。

## 现在能上线哪一种

| 形式 | 当前结论 | 还需完成 |
| --- | --- | --- |
| H5公开课程演示 | 已有可访问入口，可作备用 | 展示设备实际走查，明确演示边界 |
| 本机真实业务演示 | 后端已实现，可现场演示 | 保持主机运行；物理双设备另验 |
| 公网真实多人H5 | 暂不能按现状直接上线 | HTTPS公共源/反代适配、实际部署与公网双设备验收 |
| 微信体验版 | 可准备上传测试 | 后台权限核实、可达后端、真机性能与流程验收 |
| 微信正式版 | 当前不能宣布已具备正式上线条件 | 首发范围、后台类目/隐私配置及审核结果核验 |

公网真实版继续沿用Node+SQLite即可，不强制使用微信云开发。当前服务端把公共源固定成HTTP和内部端口，重定向、来源验证与图片URL均依赖它；仅添加HTTPS反向代理仍可能产生降级跳转或403。需要先适配显式HTTPS公共源、可信反代和真实客户端限流，再部署持久磁盘、进程管理及备份，并用两个外部账号验收。服务器和域名尚未提供，本轮未创建、购买或发布公网真实服务。

首发保留四屋核心业务；衣柜真实奖励/兑换/穿戴、活动报名等未实现功能，应实现或经确认移出首发范围。独立账号已真实验证密码，未配置微信登录本身不能直接推定审核不通过；平台后台与审核状态尚未核验，不能承诺必过。性能问题及黄色兼容警告见[验证记录](verification.md)，构建通过不能替代性能或审核验收。

依据：[uni官方双端发布说明](https://uniapp.dcloud.net.cn/quickstart.html#发布为h5)、[GitHub Pages静态托管说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。最新微信后台要求按实际账号核实；本次未以第三方文档替代其审核结果。
